GitHub Copilot をエージェントモードで使うと、コードベースを調べ、変更を提案し、ファイルを編集して、コマンドを実行します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集がリアルタイムに表示されます。差分を確認し、個々の変更を採用または却下できます。エディターを離れずに、追加のプロンプトを送って作業を調整したり拡張したりできます。

この演習では、次の操作を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッション中にエージェントへ追加の指示を送り、ハイコントラストに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使用したアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから新たな依頼がありました。既定のテーマが暗すぎると感じる利用者のため、ライトモードの切り替えも追加してほしいとのことです。新しい会話を始める代わりに、既存のセッションに追加の指示を送り、作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べているファイル、実行するコマンド、提案する編集など、各ステップが表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントの作業中、チャットをスクロールしてツールの実行状況を確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、チャットに差分が表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントにもう一度試すよう依頼します。
4. チャット上部の **Files changed** を開くと、セッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ツールの実行 (例: ターミナルコマンド) に許可が必要な場合、エージェントは一時停止し **Allow** を表示します。内容を確認し、実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容を要約するメッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けるため、エージェントは前の作業のコンテキストを保持しています。変更したコンポーネント、採用したスタイル、設定した local storage の方法などが含まれます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認します。各差分で **Keep** または **Undo** を使います。
4. エージェントが意図しない方向に進んだ場合 (例: 好みに合わない方法でトグル UI をリファクタリングする場合) は、チャット入力欄の横にある **Stop** を選択して停止し、補足プロンプトを送ります。

> [!TIP]
> 進行中のセッションに指示を送るほうが、最初からやり直すより短時間で済みます。追加プロンプトで調整を依頼できます (例: 「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」)、方針を修正できます (例: 「トグルを 3 つにせず、ライトモードを既存の設定パネルに追加する」)、範囲を拡張できます (例: 「両方のトグルにキーボードショートカットも追加する」)。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが含まれます。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが指示したアクセシビリティパターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など) が反映されていることを確認します。
4. 問題がなければ **Source Control** パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、進行中のセッションを監視して調整しました。ファイル編集を確認し、変更を採用または却下し、コンテキストを維持したまま追加プロンプトで作業を拡張しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視する
- 個々のファイル編集を採用または却下する
- 追加プロンプトを送って進行中のセッションを調整する

次のレッスンでは、アクセシビリティの変更をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
