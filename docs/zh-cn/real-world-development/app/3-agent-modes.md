我们先为项目添加了一项小功能，但更复杂的更改需要更完善的流程。GitHub Copilot app 支持组织现有的工作流，帮助我们用正确的方法构建所需功能。从本课开始，你将通过几节课遵循典型的智能体驱动开发流程：先使用议题生成新功能，确认代码有效且功能符合预期，最终将更改成功合并到项目中。

> [!NOTE]
> 后续的功能工作流都将使用同一个会话。通常，不同类型的文件会使用不同会话或 PR，但这里会适当简化，以便专注于核心概念。

本课将学习如何：

- 从 GitHub 议题启动新的智能体会话。
- 在 **Plan** 模式中定义需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

继续实现此功能时，还会更新存储库说明、自定义现有的 `quality-checks` 技能、添加 MCP 验证、创建 QA 智能体并创建功能 PR。

## 场景

Tailspin Toys 的游戏目录不断扩大，访问者需要按类别和发行商缩小游戏范围。待办事项中的议题描述了此功能，但组合类别等细节需要在编码前确定。你将使用 Plan 模式商定这些内容，然后授权 Copilot 使用 Autopilot 实现范围明确的任务。

## 背景

在开发流程中引入 AI 编码智能体并不会改变基本原则。事实上，这些原则变得更加重要！大多数开发人员都会遵循类似的流程：

1. 打开已创建的议题，查看需要完成的工作详情。
2. 制定实施计划。
3. 构建并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求 (PR)。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 具体流程会因团队和组织而异，但大多数流程都与上述内容相似。

坚持这种标准流程，可以确保 AI 生成的代码满足需求，并经历与手写代码相同的审查过程。

## 会话模式

**会话模式**控制智能体的自主程度。可以从提示字段下方的下拉菜单中设置模式，并随时更改：

- **Interactive**：你和智能体协作。智能体提出更改建议，并等待你输入后再继续。
- **Plan**：智能体先创建计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体完全自主工作——编写代码、运行测试并不断迭代，无需等待输入。

先在 Plan 模式中审查计划，再使用 Autopilot 实现。

## 从议题启动会话

开始前，确认星级评分 PR 已经合并，并且本地 `main` 已更新。

1. 在侧边栏 **Sessions** 下选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是预先创建的议题，无需再创建一个。
2. 选择 **New session**，并选择基于已更新 `main` 的**新工作树**。

    ![GitHub Copilot app 议题视图中，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认议题已附加到会话，并在模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果它们在终端中可用，但在会话中不可用，请检查应用的 PATH 或版本管理器设置，然后完全退出并重新打开应用。重试失败的操作和检查；不要仅仅因为智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

规划让你可以在 Copilot 编写代码前审查实施方案。由于会话从议题启动，Copilot 已获得功能请求的上下文。发送：

```plaintext
Build this feature.
```

回答 Copilot 的问题，并对照议题的验收标准审查计划。确认计划涵盖类别和发行商筛选、无障碍控件、数据访问更改及测试。讨论尚不明确的行为，例如多个类别如何组合，或没有匹配游戏时如何处理。

计划应使用项目现有工具运行 lint、单元测试、E2E 测试和类型检查。将范围限制为实现并测试筛选功能；完成质量工作流后再创建 PR。批准前先要求修改不符合决定的计划，并保留议题 URL 及达成一致的说明，供后续验证使用。

## 明确批准 Autopilot

确认计划符合预期后，选择 **Approve and implement this plan**，或当前版本中的等效选项。不要假定批准计划会自动切换模式；确认活动模式指示器显示 **Autopilot**。

Copilot 会开始实现功能。它将按既定计划逐步工作、生成代码并运行测试。

> [!NOTE]
> 批准后可能会立即开始实现，因此请先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决设置问题，再将检查视为已完成。只停止自己启动的服务器。

## 审查并验证实现

代码生成后，和其他代码一样，合并前需要审查。现在检查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能实现和测试。
2. 将结果与议题和已批准的澄清进行比较，包括多类别和发行商组合。确认更改符合现有存储库说明。
3. 检查 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不能算通过。
4. 接受实现前解决失败项，并重新运行受影响的检查。Playwright 的 E2E 配置会构建并提供预览服务，且可能复用本地服务器；确认被测服务器属于此工作树，而不是之前课程启动的服务器。

## 试用新功能

代码看起来没问题，但能否正常运行？像之前一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示让 Copilot 启动应用，并在浏览器画布中打开页面：

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. 稍等片刻，应用将启动，Copilot app 内会打开浏览器窗口。
3. 选择一个类别，确认结果符合类别。清除筛选后选择一个发行商，确认结果符合该发行商。
4. 组合类别和发行商筛选，并对照议题和已批准的计划检查结果。如果支持多个类别，还要验证已商定的组合行为。
5. 测试没有匹配游戏的组合，检查空结果状态。清除或重置筛选条件，确认完整列表恢复。
6. 完成后，使用以下提示让 Copilot 停止它为此会话启动的开发服务器，并关闭浏览器画布：

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 保留此会话供后续课程使用

暂时不要创建或合并筛选功能 PR。保留此会话、工作树和分支，供第 4 到第 8 课继续使用。接下来会将自定义说明应用到筛选代码，然后添加技能和 QA 改进，并在第 8 课创建和合并整合后的 PR。停止开发服务器后，可以让会话保持空闲，并在下一课返回同一会话。

## 总结和后续步骤

你使用不同的智能体模式构建并审查了功能。本课中，你：

- 从 GitHub 议题启动了新的智能体会话。
- 在 **Plan** 模式中定义了需求。
- 使用 **Autopilot** 模式实现了新功能。
- 审查了代码。
- 在浏览器画布中手动验证了功能。
